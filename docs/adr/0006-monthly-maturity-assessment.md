# ADR-0006：成熟度按团队、活动和月份独立维护

## 状态

已接受（2026-09-15）

## 背景

研发总览需要先比较活动/能力点的整体成熟度和团队短板。成熟度是人工维护的判断，不应从事实指标或某个单一指标反推，也不能因为展示四舍五入而跨越等级边界。

## 决策

- 成熟度记录的唯一粒度为 `团队 × 活动 × 评估月`，活动同时覆盖八项关键研发活动和七项通用研发能力。
- 分值范围为 0–5，最多两位小数，后端以规范化十进制字符串保存并使用 Decimal 计算。
- 团队等级为分值 floor；领域平均只纳入已评估团队，按团队等权平均后再 floor。缺失不等于 0。
- 新评估月不自动继承上月。复制上月必须是显式动作，并在预览确认后保存；清空通过删除当月记录恢复未评估。
- 领域聚合在后端完成。旧 `/api/compute` 的 `company_average` 语义不变，新增 `domain_summary` 表达原始分子/分母合并后的独立领域口径。
- 迁移只创建成熟度存储，不生成历史评估。

## 后果

总览可以在领域视角和团队矩阵之间切换，并清晰表达部分评估和无数据月份；维护权限需要在后端按 admin、maintainer、viewer 再次校验。未来若要引入自动评分，应新增独立来源和口径，不能覆盖人工评估记录。
