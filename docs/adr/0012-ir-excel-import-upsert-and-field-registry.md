# ADR-0012: IR Excel 导入采用显式更新模式与字段注册表

## Status
Accepted

决策日期：2026-10-20。决策来源：用户确认“重复导入提供两种模式，默认覆盖非空”，并要求以提供的 IR 模板作为导入和列表格式。

## Context

[ADR-0004](0004-staged-import-and-field-merge.md) 规定文件导入和自动采集都先进入临时批次，按需求编号命中正式记录时只补空字段，不覆盖已有值。该规则适合自动采集的增量补全，但不能满足用户以 Excel 为工作副本反复上传修正数据的场景：已存在字段的新值会被静默丢弃。

用户提供的 IR 模板包含 21 列，覆盖需求类型、所属功能、进展、归属组、PI、迭代、SA/SE 人员、SA/SE 工作量、AI质检等级、AI适用性、SA/SE 是否使用AI、AI研发模式、设计时间和备注。当前后端字段、表头别名和前端表单各自硬编码，新增字段容易产生前后端漂移。项目当前没有第三方 Excel 依赖，文件解析和模板生成使用标准库。

## Decision

1. 文件导入提供两种显式更新模式：
   - `upsert`：文件导入默认模式。命中需求编号时，非空 Excel 值覆盖正式值，空值保留正式值。
   - `fill_empty`：沿用 ADR-0004 的只补空语义。
   - 自动采集批次固定 `fill_empty`，不受文件导入默认值影响。
2. 预览阶段把模式保存在批次上，并计算 `insert / update / unchanged / invalid` 差异；确认阶段按同一模式整批事务执行。任意错误行阻止整批确认。
3. 引入后端字段注册表 `backend/app/ir_fields.py`，作为字段标签、表头别名、类型、必填、枚举、模板表头和 `GET /api/data/ir/schema` 的单一来源。导入模板由同一注册表生成。
4. 模板只保留一个“设计时间”列，复用现有 `completed_at` 作为时间锚点和月度统计依据；不新增 `start_date` 或 `end_date`，避免同一时间存两份。
5. 归属组、PI、迭代严格匹配现有主数据，不自动创建；缺失项在预览中列出并提示维护入口。
6. SA/SE 人员从“姓名 工号”解析为姓名与工号；工号未匹配团队成员只警告，不阻断整批。

## Alternatives Considered

- **保持只补空，不提供覆盖**：遵循 ADR-0004，但用户反复上传修正版时无法更新已有字段，仍需逐条页面编辑，未采用。
- **只允许页面编辑更新**：避免覆盖风险，但批量修正成本高，未采用。
- **导入时自动创建缺失团队/版本/迭代**：降低首次导入前置工作，但容易产生重复主数据且无法可靠推导产品归属，未采用。
- **新增独立 `design_date` 字段**：语义更纯，但与 `completed_at` 重复存同一时间；现有指标和采集契约都使用 `completed_at`，本期改为复用并统一显示名，未采用。
- **引入 openpyxl 读写 Excel**：实现更简单，但增加运行时依赖；现有标准库解析已覆盖基础 XLSX，本期通过注册表、日期序列号和模板契约测试增强，未采用。

## Consequences

- ADR-0004 中“文件导入只补空”的规则被本 ADR 部分取代；临时批次、整批确认、错误行阻断和审计规则继续有效。
- 覆盖模式会改变已有值，风险通过显式模式、预览差异、整批确认、权限校验和审计降低。
- 严格引用校验会增加首次导入的前置维护工作；以可操作的缺失项提示换取数据一致性。
- 字段注册表成为新增字段的入口；修改字段时必须同步注册表、迁移、前端渲染和测试。
- SA/SE 工号匹配失败允许入库但标记待匹配，保持与现有责任人工号一致的处理方式。
