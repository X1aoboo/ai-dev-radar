# 团队效能分析与成熟度

## 目标和边界

比较多个团队的 AI 研发效能、活动成熟度和短板，提供总览、团队下钻及指标详情。覆盖关键研发活动和通用研发能力；成熟度为人工判断，不是指标推导。当前看板仍基于 FactRecord，不能将 IR 工作台的更新描述为已自动影响看板。

## 核心场景

洞察拆为三个同级入口：`/` 研发总览面向管理者按“上下文与筛选 → Signal 摘要 → Insight 趋势卡 → 活动对照/能力指标 → 深入分析”展示选定分析月份；`/analytics/activities` 独立展示关键研发活动；`/analytics/capabilities` 独立展示通用研发能力。页头的 `month` 同时驱动成熟度和月度事实，活动与能力页面共用该月份；成熟度写入迁移到数据管理下的 `/data/maturity`。Signal 摘要只展示数量和最高级别，详情在默认关闭的右侧抽屉中按优先级提供证据。Insight 卡展示成熟度领域平均或真实指标的当前值、环比、近六个月趋势以及 best/weak 项。当前没有目标或外部行业基准，页面不输出达标、优秀或行业排名判断。

Signal 顺序为负提效、成熟度/事实缺失、低于领域团队均值的团队-活动组合；每个有指标事实的信号可下钻到证据，相对差距只称“相对靠后”，有权限的成熟度缺失可进入维护。关键研发活动用 8 项活动对照矩阵把成熟度、AI 渗透率/活动比率、提效率、数据状态和下钻放在同一行，多率指标分行，不跨活动计算虚假平均。通用研发能力按目录实际类型展示比率、数量、布尔状态或成熟度，不渲染不存在的空提效模块。选定月份没有事实时显示明确空状态，不回退到其他月份；趋势窗口缺失保留断点，不补零。成熟度雷达和能力点明细组成能力画像；缺失轴不补零。

完整团队×能力点矩阵默认收起，展开后包含领域平均行；桌面固定团队列，移动端保留局部横向滚动提示。活动页固定自然月/近六个月；能力页原始指标可切换月近六个月、周近十二周、日近三十天，成熟度仍固定按自然月。版本、迭代筛选、完整指标比较和趋势图位于“深入分析”折叠区。团队下钻查看团队趋势；指标详情按目录类型展示率、数量柱图或布尔状态。团队、版本、迭代、时间粒度与时间字段影响对应事实查询；通用研发能力不支持迭代维度。

## 指标规则

- 每个逻辑键优先最新人工事实，否则取最新自动事实；同时间按 ID 决定顺序。关键活动键为团队/指标/迭代，纯时间键为团队/指标/开始与结束日期。
- 日/周/月按选定开始或结束日期归属，日期采用 Asia/Shanghai；迭代按标签归属，不按日期重新分配。日周期是自然日，空档保留为空周期。
- 渗透率/比率为合计分子除以合计分母，分母非正返回空值。数量为合计分子。效率为 `(合计预估 - 合计实际) / 合计实际`；实际非正时使用 0.5 人天，二者均为 0 时返回空值。
- `company_average` 保留各非空团队指标值的算术平均；`domain_summary` 合并团队原始数再计算，二者不能混用。
- 总览事实基线固定使用选定月份的 `company_average`；`domain_summary` 不作为总览展示口径。有效团队数从同月团队点计数，空值不补零。
- 布尔指标使用最近有效状态，空值不当作 false；不生成全公司均值趋势。数量柱图仅用于指标详情。

## 成熟度规则与生命周期

记录唯一粒度是团队/活动/评估月。分值 0–5，最多两位小数；保存规范化十进制字符串，使用 Decimal 计算。团队等级为 floor；领域按已评估团队等权平均后 floor，展示四舍五入不影响等级。未评估不等于 0，部分评估需要保留覆盖信息。

新月份不自动继承。维护者可显式预览并复制上月，确认后保存；清空删除对应月记录，恢复未评估。admin 可维护全部团队，maintainer 仅绑定团队，viewer 只读；后端再次校验权限。
