# 团队效能分析与成熟度

## 目标和边界

比较多个团队的 AI 研发效能、活动成熟度和短板，提供总览、团队下钻及指标详情。覆盖关键研发活动和通用研发能力；成熟度为人工判断，不是指标推导。当前看板仍基于 FactRecord，不能将 IR 工作台的更新描述为已自动影响看板。

## 核心场景

洞察拆为三个同级入口：`/` 研发总览面向管理者按“分析筛选 → 月度核心成效 → 周期整体成效 → 核心指标趋势 → 关键研发活动 → 团队表现 → 成熟度矩阵与领域画像”阅读。四张 KPI 卡仅引用当前目录的 `cd-ar-pen`、`cd-eff`、`tce-count`、`tcg-rate`，名称包含所属活动和真实指标名；它们不是跨活动的全局 AI KPI，也不构造综合分。当前没有业务 Target 或外部行业基准，因此不展示目标达成或外部基准结论。`/analytics/activities` 使用八项关键活动的垂直目录；选中活动后呈现该活动的真实指标成效、同指标趋势、单周期团队差异及原始量证据。`/analytics/capabilities` 使用能力结构目录选择单项通用研发能力，按目录指标类型展示当前状态、演进、团队差异、证据和独立成熟度。

页面内容区的 PageHeader 负责标题和描述。Dashboard/Analytics 使用流式内容画布及响应式 gutter；Operational 保留表格/操作密度，Readable 用于可读宽度受限的表单。主文档负责 Analytics 纵向滚动；活动与能力目录固定在内容左侧并只管理当前选择，不创建嵌套纵向滚动区。活动页“分析筛选”按统计维度、时间粒度、指标和周期分组；维度、粒度、版本/迭代、周期和所选指标写入 URL。总览的 `month`、`cycle` 和 `version` 也由 URL 保存；`month` 锚定时间事实窗口并选择成熟度自然月，周期选项为近六个月、本半年度、年度累计，所有窗口截至用户选定月份。总览月度 KPI 直接使用该月同指标 `company_average`；周期指标先按团队汇总同一指标原始事实，再对有效团队结果取算术平均。渗透率/比率由分子分母合计后计算，效率沿用现有汇总公式，数量周期变化显示当月 `company_average`（团队等权月度新增），不跨团队合计为组织总数。周期比例/效率变化是纳入当月前后的累计结果差。事实图表使用多团队序列及同指标 `company_average`；成熟度仍按所选自然月计算。版本筛选只作用于有迭代归属的关键活动事实，通用研发能力没有版本范围。能力页原始指标的粒度控制也位于“分析筛选”工具栏中；成熟度写入迁移到数据管理下的 `/data/maturity`。

活动页的目录选择范围为当前八项关键研发活动；选中项展示它的真实指标，不把成熟度、渗透率、效率、数量或比率跨活动平均。`company_average` 保留在同指标团队趋势和团队差异中；合并原始量与团队均值分别呈现。通用研发能力按目录实际类型显示：数值类指标保留各自单位与事实，布尔能力逐团队显示已具备/不具备/未知状态，不渲染不存在的 0/1 趋势。选定月份没有事实时显示明确空状态，不回退到其他月份；趋势窗口缺失保留断点，不补零。成熟度为独立人工评估，能力页仅显示所选能力的成熟度演进；缺失轴不补零。

总览核心趋势在四个 KPI 指标间切换，并同时展示该指标的全部团队序列与 `company_average`。关键活动区从实际目录选择一项活动，同时展示它已有的目录指标；选中后，这些指标各自以团队序列和 `company_average` 并排演进，不把不同单位合成阶段分数。团队表现矩阵各列保留一个独立指标，可在本月与统计周期间切换；选中团队后预览该团队的渗透率、效率趋势，并可进入现有 Team Drill-down。成熟度区按关键活动或通用能力切换，分别显示团队矩阵和本期、上期领域平均雷达；未评估仍为空值。

完整团队×能力点矩阵默认收起，展开后包含成熟度领域平均行；桌面固定团队列，移动端保留局部横向滚动提示。活动页支持按时间或版本/迭代筛选，时间粒度为月/周/日，周期可选全部或单周期，指标可切换为全部或单项；时间窗口分别为近六个月、近十二周、近三十天，成熟度始终按独立的自然月。通用研发能力原始指标可切换月/周/日，成熟度仍固定按自然月；布尔能力使用团队状态列表，不绘制 0/1 折线或全公司均值。Team Drill-down 以“整体表现 → 研发关键环节 → 成熟度画像”组织单页故事线，并提供 sticky 锚点导航。两行 KPI 均引用现有 `cd-ar-pen`、`cd-eff`、`tce-count`、`tcg-rate` 四个单指标，显示当前团队值和同指标 `company_average` 基准，不生成跨指标综合值；月度按所选自然月读取，周期按团队原始事实累计到所选月份，数量变化显示当前月新增，比例/效率变化比较加入当前月前后的累计结果。整体表现的两张趋势图以当前团队为主序列、`company_average` 为基准；研发关键环节选择一个实际活动，并并列展示该活动已有的渗透率和效率指标趋势。成熟度画像分别展示关键活动、通用能力的团队与领域平均矩阵和雷达；团队记录取所选自然月，领域平均沿用成熟度 API，未评估分值保留为空。指标详情按 Result → Comparison → Evidence 展示：当前全公司均值、同指标趋势与单指标团队排名/状态，以及按需展开的当前周期原始事实。量化详情分列 `company_average` 与 `domain_summary` 的结果、原始分子/分母；前者为团队结果算术平均，后者合并原始量后重算，不互相替代。目录类型仍决定率、数量或布尔展示。团队、版本、迭代、时间粒度与时间字段影响对应事实查询；通用研发能力不支持迭代维度。

图表按分析任务而非指标存储类型选择：时间演进优先折线，单周期团队排名使用单指标排序，布尔能力使用状态列表；数量指标不因类型被强制改为柱状趋势。

## 指标规则

- 每个逻辑键优先最新人工事实，否则取最新自动事实；同时间按 ID 决定顺序。关键活动键为团队/指标/迭代，纯时间键为团队/指标/开始与结束日期。
- 日/周/月按选定开始或结束日期归属，日期采用 Asia/Shanghai；迭代按标签归属，不按日期重新分配。日周期是自然日，空档保留为空周期。
- 渗透率/比率为合计分子除以合计分母，分母非正返回空值。数量为合计分子。效率为 `(合计预估 - 合计实际) / 合计实际`；实际非正时使用 0.5 人天，二者均为 0 时返回空值。
- `company_average` 保留各非空团队指标值的算术平均；`domain_summary` 合并团队原始数再计算，二者不能混用。
- `/api/compute` 每个团队/周期事实点提供 `fact_count`；无事实的数量点保持缺失，已记录的数量事实 0 保持为 0。`company_average` 只平均该周期有事实且结果有效的团队。
- 总览事实基线固定使用选定月份的 `company_average`；`domain_summary` 不作为总览展示口径。有效团队数从同月团队点计数，空值不补零。
- 未设置单周期的布尔能力当前状态使用最近有效 `snapshot`；明确选择单周期的布尔详情读取该周期 `series.values`。缺失保持未知、不当作 false，也不回退到其他周期；布尔指标不生成全公司均值趋势。数量柱图仅用于指标详情。

## 成熟度规则与生命周期

记录唯一粒度是团队/活动/评估月。分值 0–5，最多两位小数；保存规范化十进制字符串，使用 Decimal 计算。团队等级为 floor；领域按已评估团队等权平均后 floor，展示四舍五入不影响等级。未评估不等于 0，部分评估需要保留覆盖信息。

新月份不自动继承。维护者可显式预览并复制上月，确认后保存；清空删除对应月记录，恢复未评估。admin 可维护全部团队，maintainer 仅绑定团队，viewer 只读；后端再次校验权限。

## 数据与实现映射

目录 Activity/Metric、FactRecord、Team、ProductVersion/Iteration 支持事实查询；MaturityRecord 独立支持评估。

本地演示种子按执行时的 Asia/Shanghai 当前月生成近六个月事实与独立的成熟度模拟评估，覆盖四个团队及目录中全部活动和指标；当前月的事实落在执行当天。演示评估只用于界面预览，不由事实指标推导，也不改变正式评估的人工维护规则。跨入新月份后须重跑种子才覆盖新的默认月份；该命令会重建业务数据。
